## Objectif
Dans `src/orchestrator.py`, l'étape `validation_classification` fait aujourd'hui **deux boucles**
sur les messages de la synthèse : `_recalculer_empreintes` (un `get_message` API par message pour
le recalcul C6) puis `_appliquer_libelles_classification` (pose catégorie + `Agent/traité`).
Fusionner en **une seule passe** : `get_message` → recalc C6 (rejet si écart) → `modifier_libelles`.

## Règles
- Invariants conservés : recalc depuis la **lecture API réelle** (C6 anti-hallucination), ordre
  recalc-avant-libellisation (aucun libellé posé si C6 rejette), dry-run (règle E : écritures
  journalisées seulement).
- Aucun changement de comportement externe (mêmes rejets, mêmes libellés, mêmes logs).

## Plan
1. `src/orchestrator.py` : remplacer les deux appels/étapes par une fonction unique
   `_valider_et_labelliser_classification(synthese, resolveur, api)` (une boucle).
2. Tests (`tests/unit/test_orchestrator.py`) : un seul `messages.get` par message ; rejet C6
   avant toute écriture ; dry-run sans écriture ; libellés posés en `--reel` simulé.
3. Vérifications : `ruff check src tests`, `mypy src`, `pytest tests -q` ; kanban → En revue ;
   commit/push sur `dev` sur demande explicite (règle C).
