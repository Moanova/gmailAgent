## Contexte technique (vérifié en séance)

### Structure des sorties de conversation (SDK mistralai 3.5)

`ConversationResponse.outputs` est une liste d'entrées typées (union) :

| Type d'entrée | Classe SDK | Champs clés |
| --- | --- | --- |
| `message.output` | `MessageOutputEntry` | `content` (str ou chunks), `role: "assistant"` |
| `tool.execution` | `ToolExecutionEntry` | `name` (nom de l'outil), `arguments` (str JSON), `info?` (dict optionnel) |
| `function.call` | `FunctionCallEntry` | `name`, `arguments`, `tool_call_id` |
| `agent.handoff` | `AgentHandoffEntry` | (non utilisé — pas de handoffs, décision D1) |

**Point clé** : dans une conversation éphémère avec connecteur, l'entrée
`tool.execution` porte le **nom de l'outil** et ses **arguments sérialisés en
JSON string** — le résultat de l'outil n'est pas dans l'entrée (il est exécuté
côté connecteur et réinjecté dans la conversation par le moteur).

### Noms d'outils Gmail (conception §1.1)

| Outil | Rôle | Arguments pertinents pour `collecter_ids_reels` |
| --- | --- | --- |
| `search_threads` | Rechercher des threads | `query`, `max_results` — **pas d'ID** (retourne des IDs, mais côté résultat) |
| `get_thread` | Lire un thread | `threadId` (ou `id`) — **ID manipulé** |
| `label_message` | Apposer/retirer un libellé sur un message | `messageId`, `labelIds`/`labelId` — **IDs manipulés** |
| `label_thread` | Apposer/retirer un libellé sur un thread | `threadId`, `labelIds` — **IDs manipulés** |
| `list_labels` | Lister les libellés | aucun — **pas d'ID** |

> **Note** : les noms exacts (préfixe `gmail_` ou non) et les noms de champs
> d'arguments (`threadId` vs `id`, `messageId` vs `message_id`) seront à
> confirmer au premier appel réel (phase 3+). La fonction
> `collecter_ids_reels` accepte donc une **allow-list configurable** de
> champs d'arguments à extraire, par défaut couvrant les variantes usuelles.

### Ce que la validation ne fait PAS

- Elle ne recalcule pas les empreintes de dédoublonnage (phase 6, `dedup.py`)
  — mais elle vérifie la **présence et la forme** de `message_id_rfc` et
  `empreinte` dans la synthèse de classification.
- Elle ne valide pas le contenu sémantique (catégorie pertinente, motif
  justifié) — c'est le rôle du LLM + du prompt.

## Plan d'implémentation

Créer `src/validation.py` avec :

### 1. `extraire_json(texte: str) -> dict`

Extraction robuste du **premier objet JSON bien formé** dans un texte :

- Recherche du premier `{` ouvrant une paire accolades équilibrée (gestion
  des accolades imbriquées et des chaînes avec échappements) ;
- `json.loads` sur le candidat ; en cas d'échec, recherche de l'occurrence
  suivante ;
- Lève `ExtractionJsonError` si aucun objet valide trouvé.

### 2. `collecter_ids_reels(outputs: list) -> set[str]`

Parcours des entrées `tool.execution` (et `function.call` en secours) pour
recueillir les **identifiants réellement manipulés** :

- Filtre sur `entry.type == "tool.execution"` (ou `"function.call"`) ;
- `json.loads(entry.arguments)` (arguments est un str JSON) ;
- Pour chaque champ d'argument dans l'allow-list
  (`threadId`, `thread_id`, `id`, `messageId`, `message_id`) : collecte la
  valeur (str) ou les valeurs (list) ;
- Retourne un `set[str]` (dédupliqué).

> L'allow-list est une constante module, modifiable si les noms de champs
> Gmail diffèrent au premier appel réel.

### 3. `valider_synthese(synthese: SyntheseEtape, ids_reels: set[str]) -> None`

Contrôles, dans l'ordre (premier échec = rejet avec motif explicite) :

| # | Contrôle | Règle |
| --- | --- | --- |
| C1 | Non-contradiction statut/messages | `echec_technique` → `messages` vide ET `erreur` non vide ; `synthese`/`deplaces`/`supprimes` → `erreur` vide |
| C2 | Non-contradiction statut/erreur | `aucun_message` → `messages` vide ET `erreur` vide |
| C3 | Complétude | `synthese`/`deplaces`/`supprimes` → `messages` non vide (ou `count > 0` + `ids` non vide pour suppression) |
| C4 | Authenticité des IDs | chaque `message.id` (ou `ids[]` pour suppression) ∈ `ids_reels` |
| C5 | Cohérence suppression | `count == len(ids)` |
| C6 | Cohérence classification | chaque `MessageClasse` a `message_id_rfc` et `empreinte` conformes (déjà garanti par le pattern Pydantic, double vérification défensive) |

Lève `SyntheseInvalideError(motif)` en cas d'échec. Le motif est
journalisation-friendly (une ligne, pas de contenu utilisateur).

### 4. Exceptions

- `ExtractionJsonError(ValueError)` — aucun objet JSON trouvé.
- `SyntheseInvalideError(ValueError)` — contrôle C1–C6 échoué (avec motif).

### 5. `pyproject.toml`

Ajouter `"validation"` à `py-modules`.
