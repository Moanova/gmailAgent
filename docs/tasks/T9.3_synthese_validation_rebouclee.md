## Objectif
Incident réel du 10/11/2026 (run `d9fafc4a-861b-4d30-b974-d0aaf175ab8b`, `--tout --reel`, étape
`lecture_classification`) : la synthèse de classification citait les `message_id_rfc` avec
chevrons (`<…@laposte.net>`) — l'exemple du prompt (`<abc@exemple.fr>`) contredisait le pattern
strict du contrat (`^[^<>\s]+@[^<>\s]+$`) ; le `ValidationError` de `construire_synthese`
n'étant pas rattrapé dans `lancer_conversation`, il a interrompu le run. Deux correctifs :
normaliser au lieu de rejeter, et reboucler toute erreur de validation de synthèse vers le modèle.

## Règles de conception
- `message_id_rfc` normalisé (`dedup.normaliser_message_id` : sans `<>`, espaces, minuscules)
  avant `model_validate` dans `construire_synthese` — cohérent avec le recalcul C6
  (`_recalculer_empreintes` normalise déjà la valeur de la synthèse).
- Exemple du prompt corrigé (`abc@exemple.fr`, sans chevrons) pour lever la contradiction.
- Toute erreur de la chaîne `extraire_json` → `_normaliser_payload` → `construire_synthese` →
  `valider_synthese` (`ExtractionJsonError`, `SyntheseInvalideError`, `ValidationError`) est
  renvoyée au modèle (UserMessage de retour + warning `synthese refusee : validation`), décomptée
  dans `max_tentatives_synthese` (3) — abandon propre au-delà (même pattern que D56).
- Les gardes existantes (threads non lus, écart corbeille/ids, messages lus non classés)
  sont inchangées et partagent le même compteur de tentatives.
