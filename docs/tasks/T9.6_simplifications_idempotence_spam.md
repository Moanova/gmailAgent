## Contenu prévu
1. **Factorisation des branchements orchestrateur** (`src/orchestrator.py`) :
   `_lancer_spam` / `_lancer_classification` / `_lancer_suppression` (~25 lignes chacun, quasi
   identiques) → un seul helper `_lancer_etape(agent, etape, requete, *, dry_run, client_api,
   client_mistral, conversation)`.
2. **Bloc « lecture » commun aux 3 prompts** (`src/prompts.py`) : la partie « Obligatoire :
   `search_threads`, puis `get_thread` sur chaque thread… » est recopiée à l'identique dans
   `prompt_classification` / `prompt_spam` / `prompt_suppression` → factoriser en un bloc
   injecté (les enums/règles spécifiques restent par prompt).
3. **À arbitrer avant implémentation** : court-circuit `aucun_message` sans appel au modèle
   quand `search_threads` renvoie 0 thread (économie d'appels LLM par run ; contourne C1–C6,
   trivial sur liste vide).
4. **Fonctionnalité — idempotence du spam** : les spams laissés en spam (`aucun_message`)
   sont re-lus à chaque run (`spam.requete: in:spam`, aucune clause d'exclusion — constaté
   dans les logs du 10/11 : même thread relu 3× ; borné par le cap 23 depuis D58). Proposition :
   - nouvelle clé logique `suivi.spam-confirme` dans `config/labels.yaml` (ex.
     `Agent/spam-confirme`) ;
   - `_appliquer_libelles_spam` : si statut `aucun_message`, poser `spam-confirme` sur les
     messages lus et laissés en spam (SPAM conservé) ;
   - `spam.requete` devient `in:spam -label:"<spam confirmé>"` (libellé résolu via le registre,
     jamais en dur dans la requête — cf. `requete_non_lus`).
5. **Approuvé le 10/11/2026 (D59)** : supprimer la clause inerte `OR label:"Agent/doublon"` de
   `requete_suppression` (D46, phase 6 post-v1 — à ré-ajouter à la reprise) et l'appel
   `resoudre(CLE_DOUBLON)` associé ; tests à mettre à jour (`REQUETE_SUPPRESSION` dans
   `test_agents.py`, TI suppression, `test_orchestrator.py`).
6. **Approuvé le 10/11/2026 (D59)** : supprimer la méthode morte `corbeille()` de
   `src/gmail.py` (jamais appelée par le pipeline — le TRASH passe par `label_message`) et
   ses tests dans `test_gmail.py`.

## Réalisation (11/11/2026)
1. **Factorisation orchestrateur** : `_lancer_spam`/`_lancer_classification`/`_lancer_suppression`
   remplacés par `_lancer_etape(agent, etape, requete, rid, reg, ...)` (`src/orchestrator.py`) ;
   la requête est calculée par l'appelant (`requete_spam`, `requete_non_lus`, `requete_suppression`).
2. **Bloc prompt commun** : `_BLOC_LECTURE` (`src/prompts.py`) injecté dans les 3 prompts.
3. **Court-circuit (arbitrage, D61)** : placé dans le runner (`lancer_conversation`,
   `src/agents.py`), après un `search_threads` renvoyant 0 thread, pour les 3 agents —
   synthèse `aucun_message` produite sans appel au modèle ; `valider_synthese` (C1–C6)
   reste appliquée à la synthèse vide.
4. **Idempotence du spam** : clé `suivi.spam-confirme` → `Agent/spam-confirme`
   (`config/labels.yaml`) ; `requete_spam(registre, resolveur)` =
   `in:spam -label:"<spam confirmé>"` (base `spam.requete` de `settings.yaml` + exclusion
   résolue via le registre) ; `_appliquer_libelles_spam` pose `spam-confirme` sur les
   messages lus et laissés en spam si `aucun_message` (SPAM conservé ; dry-run : journalisé).
5. **D59** : clause `OR label:"<doublon>"` et `resoudre(CLE_DOUBLON)` retirés de
   `requete_suppression` ; méthode morte `corbeille()` supprimée de `src/gmail.py`.
