## Objectif
`src/prompts.py` : prompt conservatoire de l'agent spam. Les contrats d'outils Gmail
(`OUTILS_GMAIL`, allow-list : `search_threads`, `get_thread`, `get_message`,
`label_message`, `list_labels`) étaient déjà livrés en T5.1 et testés ; le schéma
strict `SyntheseSpam` (`deplaces`/`aucun_message`/`echec_technique`, `messages[]` =
`id`, `objet`, `expéditeur`, `motif`) est déjà construit dynamiquement par
`contracts.schema_agent(AGENT_SPAM, registre)` (T2.2).

## Plan d'implémentation

1. **Prompt spam** (`prompt_spam(registre)` dans `src/prompts.py`) :
   - conservatoire : ne retenir depuis le dossier spam (`in:spam`) que les messages dont
     la légitimité est **certaine** (ex. : newsletter connue, contact connu) ; en cas de
     doute, laisser en spam et ne rien mentionner ;
   - règles de véracité strictes : ne mentionner que des messages réellement lus via
     `search_threads` / `get_thread` (lecture de **chaque** thread retourné) ; boîte
     vide → statut `aucun_message` ;
   - **aucun nom de libellé physique en dur** : les clés logiques `suivi.valide-spam`
     et `suivi.traite` sont injectées depuis `config/labels.yaml` via le registre ;
   - consigne de moindre privilège : l'agent ne modifie aucun libellé lui-même
     (c'est l'orchestrateur qui appose en T4.3) ; ni envoi ni suppression (corbeille
     interdite) ;
   - sortie imposée : unique objet JSON racine conforme au schéma strict `SyntheseSpam`.
2. **Contrats d'outils** (`OUTILS_GMAIL` : `search_threads`, `get_thread`, `label_message`,
   `list_labels`) : schémas JSON `type=function` pour l'API Mistral (allow-list par agent,
   moindre privilège — aucun outil d'envoi ni de suppression définitive).
3. **Tests unitaires** `tests/unit/test_prompts.py` : le prompt ne contient aucun libellé
   physique en dur (assert sur les valeurs du registre), contient les règles de véracité ;
   schémas d'outils conformes (noms, paramètres requis) ; injection des libellés depuis
   le registre.
4. **Vérifications** : `ruff check src tests`, `mypy src` (strict, `py-modules += prompts`),
   `pytest tests/unit -v` ; kanban → En cours → En revue ; commit/push sur demande (règle C).
