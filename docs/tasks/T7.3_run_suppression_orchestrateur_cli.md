## Plan d'implémentation

1. **`src/orchestrator.py`** — `lancer_run_suppression(run_id=None, *, dry_run=True,
   client=None, client_api=None, client_mistral=None, conversation=None, registre=None,
   dossier_checkpoints=None) -> RapportFinal`, miroir de `lancer_run_tri` :
   - nouvelle fonction `requete_suppression(registre, resolveur)` (même principe que
     `requete_non_lus` : résolution/création des libellés via le resolveur, clés logiques
     `suivi.traite` + `suivi.doublon`, jamais de libellé physique en dur) :
     `label:"<traité>" older_than:1h label:"<doublon>"` (clause `doublon` inerte en v1) ;
   - helper `_lancer_suppression(rid, reg, resolveur, *, dry_run, client_api,
     client_mistral, conversation)` modèle `_lancer_classification` : `Meta(etape=
     "lecture_suppression", agent=AGENT_SUPPRESSION)` + `lancer_conversation(
     AGENT_SUPPRESSION, requete, ...)` ;
   - étapes du run séparé : `demarrage` (log de la requête) → `lecture_suppression`
     (synthèse persistée dans `checkpoint.syntheses["suppression"]`) → `validation_suppression`
     (la synthèse est déjà validée C1–C3 + garde action dans le runner ; ici simple
     checkpoint — l'agent a appliqué TRASH lui-même, journalisé en dry-run) → `rapport`
     (`RapportFinal` avec `synthese_suppression`, `statut_global="succes"`) → `fin` ;
     reprise sur incident par `run_id` (étapes déjà validées sautées), rejet →
     `echec_partiel` + `etape_fautive` + checkpoint persisté + relance de l'exception
     (même bloc try/except que `lancer_run_tri`) ;
   - idempotence : la requête `older_than:1h` + la recherche Gmail excluant la corbeille
     (un message déjà en TRASH n'est plus sélectionné).
