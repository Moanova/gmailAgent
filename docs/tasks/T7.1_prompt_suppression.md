## Plan d'implémentation

1. **Prompt suppression** (`prompt_suppression(registre)` dans `src/prompts.py`,
   miroir de `prompt_spam`) :
   - rôle : agent du **run de suppression planifié T+1h** ; la requête de sélection est
     fournie par l'orchestrateur (ne pas la reconstruire) ; les clés logiques
     `suivi.traite` et `suivi.doublon` sont injectées depuis le registre (aucun libellé
     physique en dur ; la clause `doublon` est inerte en v1, D46) ;
   - véracité (impératif) : appeler `search_threads` avec la requête fournie, puis
     `get_thread` sur **chaque** thread retourné (un appel par thread, sans en sauter),
     puis `get_message` sur chaque message à traiter, AVANT la synthèse ; ne retenir que
     des ids issus de ces appels réels — l'orchestrateur rejette sinon (C3, complétude) ;
   - **corbeille uniquement** : pour chaque message retenu, appliquer le libellé système
     `TRASH` via `label_message` (`addLabelIds`) ; interdiction absolue de suppression
     définitive (aucun outil ne la permet — moindre privilège) et d'envoi de message ;
   - statuts de sortie : `supprimes` avec `count == len(ids)` et `ids` = ids Gmail (champ
     `id` de l'aperçu) des messages mis à la corbeille ; `aucun_message` si la requête ne
     retourne rien (count=0, ids vide) ; `echec_technique` + champ `erreur` en cas
     d'échec — jamais de `ids` imaginaires ;
   - sortie imposée : UNIQUE objet JSON racine conforme au schéma strict
     `SyntheseSuppression`, champs `statut`, `count`, `ids` à la racine (ex.
     `{"statut": "supprimes", "count": 2, "ids": [...]}`) — jamais un tableau nu.
2. **Contrat de sortie** : rien à changer dans `src/contracts.py` ;
   `response_format_agent(AGENT_SUPPRESSION, registre)` est déjà construit et testé (T2.4,
   exclusion `meta`/`agent` testée D44).
3. **Tests unitaires** `tests/unit/test_prompts.py` — nouvelle classe
   `TestPromptSuppression` (miroir de `TestPromptSpam`, ~6 tests) :
   - clés logiques `suivi.traite` et `suivi.doublon` présentes dans le prompt ;
   - aucun libellé physique en dur (`"Agent/" not in prompt`) ;
   - statuts `supprimes`/`aucun_message`/`echec_technique` et champs `count`/`ids`
     mentionnés ;
   - corbeille uniquement : `TRASH` et `label_message` présents, suppression définitive
     interdite, ni envoi ni suppression définitive ;
   - règles de véracité (lecture de chaque thread avant synthèse) ;
   - objet JSON unique à la racine (`statut`, `count`, `ids`).
4. **Vérifications** (étape 4) : `ruff check src tests`, `mypy src` (strict),
   `python -m pytest tests -q` (210 existants + ~6 nouveaux) ; kanban T7.1
   « En cours » → « En revue » (validation agent, étape 5) ; **aucun commit** (règle C).
