## Statut
- [ ] Implémentation

- [ ] Tests d'intégration (T4.4)

## Objectif
Dans `src/orchestrator.py`, remplacer les stubs `lecture_spam` / `validation_spam` par la
vraie conversation agent spam (étapes 1–2 du pipeline, `workflow.md`).

## Plan d'implémentation

1. **Étape 1 (lecture spam)** : appeler `agents.lancer_conversation_spam(...)` sur la
   requête `in:spam` (max 50 threads) ; stocker la synthèse + les exécutions d'outils dans
   le `Checkpoint` (`syntheses["spam"]`).
2. **Étape 2 (validation spam)** : `valider_synthese` (C1–C6) ; si rejet → journaliser le
   motif + arrêt propre (chemin déjà en place : rapport `echec_partiel`, `etape_fautive`) ;
   si ok → pour chaque message `deplaces`, apposer `Agent/valide-spam` (et `Agent/traité`)
   via le resolveur + `client.modifier_libelles` (dry-run = journalisé, règle E) et
   retirer le libellé SPAM (replace dans la boîte de réception).
3. **Checkpoint** : synthèse spam persistée à l'étape validée (reprise sur incident OK).
4. **Tests unitaires** (`test_orchestrator.py` complété) : run avec agent spam mocké —
   synthèse valide → `modifier_libelles` appelé avec les bons labelIds (dry-run : non
   exécuté) ; synthèse rejetée → exception + rapport `echec_partiel` ; reprise : étape
   `lecture_spam` déjà checkpointée → pas de nouvel appel agent.
5. **Vérifications** : `ruff`, `mypy src` (strict), `pytest tests` ; kanban → En revue ;
   commit/push sur demande (règle C).
