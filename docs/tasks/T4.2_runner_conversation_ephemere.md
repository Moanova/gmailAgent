## Objectif
Brancher l'agent spam dans le runner de conversation éphémère générique
`lancer_conversation(agent, ...)` livré en T5.2 (`src/agents.py`, décision D35) :
le runner (boucle tool-calls bornée, `response_format_agent`, `construire_synthese`,
`valider_synthese` C1–C3 génériques, C6 empreintes réservée à la classification) était
déjà paramétré par agent ; il restait le prompt et une garde de complétude.

## Plan d'implémentation

1. **`_prompt_systeme`** : branche `AGENT_SPAM` → `prompt_spam(registre)` (T4.1) ;
   `AGENT_SUPPRESSION` lève encore `AgentInconnuError` (jusqu'à la phase 7).
2. **Garde de complétude « messages lus non classés » réservée à la classification** :
   pour le spam, un message lu mais laissé en spam ne figure pas dans la synthèse
   (conservatisme du prompt T4.1) — la garde ne s'applique qu'à `AGENT_CLASSIFICATION`.
   La garde threads (tout thread retourné par `search_threads` lu via `get_thread`)
   reste active pour tous les agents, spam compris.
3. **Tests unitaires** `tests/unit/test_agents.py` : sélection du prompt spam (et
   `response_format` nommé `SyntheseSpam`), conversation spam complète mockée
   (`deplaces`), `aucun_message`, message lu non retenu accepté pour le spam,
   garde threads active pour le spam, rejet C3 (id non manipulé), suppression toujours
   sans prompt.
4. **Vérifications** : `ruff`, `mypy src` (strict, `py-modules += agents`), `pytest` ;
   kanban → En revue ; commit/push sur demande (règle C).
