## Objectif

## Plan d'implémentation

1. **`executer_outil(nom, args, client_gmail)`** : dispatch vers `ClientGmailAPI`
   (`search_threads` paginé max 50/run, `get_thread`, `label_message` →
   `modifier_libelles`, `list_labels`) ; retour JSON sérialisable pour le LLM ;
   écritures neutralisées en dry-run (règle E, déjà géré côté client).
2. **`lancer_conversation_spam(client_mistral, client_gmail, registre, *, dry_run, plafond_appels)`** :
   - appel Mistral : `client.obtenir_client()` (timeout 300 s) + `avec_retry` (429/5xx,
     3 tentatives, backoff) ; `temperature=0.0`, `max_tokens` cap ; `response_format` =
     `response_format_agent(AGENT_SPAM, registre)` (strict) ; outils = allow-list T4.1 ;
   - boucle tool-calls (plafond d'appels = garde-fou anti-boucle, statut
     `echec_technique` au-delà) jusqu'à obtention d'un message final ;
   - parsing : `extraire_json` → `construire_synthese` → `valider_synthese` (C1–C6,
     avec `collecter_ids_reels` sur les exécutions d'outils réelles) ;
   - retourne `(SyntheseSpam, executions_outils)`.
3. **Tests unitaires** `tests/unit/test_agents.py` : client Mistral mocké (fixtures SDK
   `ToolExecutionEntry`/`FunctionCallEntry` comme T2.4) — boucle tool-calls, extraction
   JSON, rejet de synthèse incohérente (C1–C6), plafond anti-boucle ; faux service Gmail
   pour `executer_outil` (dry-run = aucune écriture).
4. **Vérifications** : `ruff`, `mypy src` (strict, `py-modules += agents`), `pytest` ;
   kanban → En revue ; commit/push sur demande (règle C).
