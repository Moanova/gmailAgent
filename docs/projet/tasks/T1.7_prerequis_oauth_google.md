## Détails de l'implémentation
- **Partie A — Google Cloud** (par l'utilisateur, une seule fois) : créer un projet sur
  [console.cloud.google.com](https://console.cloud.google.com), activer l'**API Gmail**
  (API et services > Bibliothèque) ; écran de consentement OAuth (Google Auth Platform >
  Écran de consentement) type **Externe** puis **« Publier l'application »** (statut
  « En production » — obligatoire : en « Testing », le refresh token expire après 7 jours ;
  l'écran « app non vérifiée » est acceptable en usage perso < 100 utilisateurs, contourné
  par « Avancé » → « Continuer ») ; créer un client **« Application de bureau »**
  (Google Auth Platform > Clients) → `client_id` + `client_secret`. Aucune facturation
  requise pour l'API Gmail en usage personnel.
- **Scopes** : `https://www.googleapis.com/auth/gmail.modify` uniquement (défini dans
  `installation/init_oauth.py`, `SCOPES`) — `gmail.send` exclu (moindre privilège).
- **Partie B — premier flux** : `python installation/init_oauth.py` ouvre le consentement dans le
  navigateur (`access_type=offline`, `prompt=consent`), échange le code contre
  `access_token` (1 h) + `refresh_token`, et écrit `data/gmail_token.json`
  (`token`, `refresh_token`, `token_uri`, `client_id`, `client_secret`, `scopes`,
  permissions 600). Garde-fous : échec propre si variables manquantes, si le fichier
  existe déjà, ou si aucun refresh token reçu.
- **Runtime** : `gmail_client.py:charger_credentials` recharge le token via
  `Credentials.from_authorized_user_info` ; `google-auth` renouvelle l'access token
  automatiquement (le `client_id`/`client_secret` embarqués dans le token servent au refresh).
  Aucune variable d'environnement Google n'est lue par `src/` (seule `MISTRAL_API_KEY` l'est,
  `core_client.py:38`).
- **Durabilité** : en « En production », pas d'expiration calendaire du refresh token ;
  invalidé si révocation, 6 mois d'inactivité, changement de mot de passe Google (scopes
  Gmail) ou plafond ~50 tokens actifs par compte/client → supprimer
  `data/gmail_token.json` et relancer `init-oauth.bat` (identifiants depuis le
  Credential Manager, ou relus dans l'ancien token par `lancer.ps1` — option A, D71).
