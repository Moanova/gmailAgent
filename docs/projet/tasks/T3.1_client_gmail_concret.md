## Détails de l'implémentation
- `charger_credentials` : recharge `data/gmail_token.json` via
  `Credentials.from_authorized_user_info` (contrat T1.7) ; `TokenGmailError`
  propre si le fichier est absent, illisible ou malformé ; chemin par défaut
  à la racine du dépôt (`data/gmail_token.json`).
- `ClientGmailAPI` : satisfait le protocole `ClientGmail` de `labels.py`
  (`list_labels`, `create_label`) et expose les opérations du pipeline :
  `search_threads` (requête d'idempotence `is:unread -label:"Agent/traité"`),
  `get_thread`, `modifier_libelles` (add/remove), `corbeille` (`trash`
  uniquement — jamais de suppression définitive). Service construit via
  `build("gmail", "v1", credentials=..., cache_discovery=False)` ; refresh de
  l'access_token automatique par google-auth.
- Dry-run (règle E de AGENTS.md) : les écritures (`create_label`,
  `modifier_libelles`, `corbeille`) sont journalisées, jamais exécutées ;
  `create_label` renvoie un id placeholder `DRYRUN:<nom>`.
- Garde-fou anti-boucle : plafond d'appels de lecture (`PLAFOND_LECTURES = 100`),
  `PlafondLecturesAtteintError` au-delà (abandon propre du run).
- `nouveau_client` : fabrique typée `-> ClientGmail` (conformance au protocole
  vérifiée par mypy).
- Itération mypy : `Credentials.from_authorized_user_info` non typé côté
  google-auth → `cast(Credentials, ...)` + `# type: ignore[no-untyped-call]`.
