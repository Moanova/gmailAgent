## Origine
Analyse T9.5 (séance du 10/11/2026), volet classification, piste n°3 — refactor à risque maîtrisé.

## Objectif
`src/agents.py`, boucle de `lancer_conversation` (~150 lignes) : remplacer les 4 mécanismes de
retour au modèle distincts par **un seul mécanisme « refus avec motif renvoyé au modèle +
compteur de tentatives »** :
- D56 : erreur d'outil → ToolMessage `{"erreur": ...}` (compteur d'appels, pas de tentatives) ;
- D57 : synthèse invalide (JSON/contrat/C1–C6) → UserMessage avec le motif ;
- garde « threads non lus » → UserMessage avec les ids manquants ;
- garde « messages non classés » (classification) → UserMessage ;
- écart corbeille/ids (suppression) → UserMessage.

Aujourd'hui ils partagent `tentatives_synthese` de façon implicite et le code se répète. Cible :
une fonction `_refuser(messages, contenu_final, motif, log_warning...)` qui append
AssistantMessage + UserMessage, incrémente le compteur, et lève `SyntheseInvalideError` au-delà
de `max_tentatives_synthese` — chaque garde n'appelant que ça avec son motif.

## Règles
- **Comportements externes inchangés** : mêmes messages envoyés au modèle, mêmes logs
  (`outil en echec`, `synthese refusee : …`), mêmes conditions d'abandon. La couverture de
  tests existante (`TestOutilEnEchec`, `TestSyntheseInvalideRebouclee`, `TestCompletudeLecture`,
  `TestCompletudeMessages`, `TestLimiteTentativesSynthese`, TI spam/classification/suppression)
  doit passer **sans modification** — c'est le critère d'acceptation principal.
- Ne pas toucher aux invariants : allow-list, périmètre de requête (D54), anti-boucle (D58),
  dry-run.
