## Plan d'implémentation

1. **`executer_outil(nom, args, client_gmail)`** : dispatch vers `ClientGmailAPI`
   (`search_threads` paginé max 50/run, `get_thread`, `label_message` →
   `modifier_libelles`, `list_labels`) ; retour JSON sérialisable ; écritures neutralisées
   en dry-run côté client (règle E).
2. **`lancer_conversation(agent, *, client_mistral, client_gmail, registre, dry_run, plafond_appels)`** :
   - appel Mistral : `obtenir_client()` (timeout 300 s) + `avec_retry` (429/5xx) ;
     `temperature=0.0`, `max_tokens` cap (1500 classification, 2000 si création de
     libellés) ; `response_format=response_format_agent(agent, registre)` (strict) ;
     outils = allow-list Gmail (T5.1/T4.1) ;
   - boucle tool-calls jusqu'au message final, avec **garde-fou anti-boucle** (plafond
     d'appels → statut `echec_technique`) ;
   - parsing : `extraire_json` → `construire_synthese` → `valider_synthese` (C1–C6, avec
     `collecter_ids_reels` sur les exécutions réelles) ;
   - retourne `(synthese, executions_outils)`.
3. **Tests unitaires** `tests/unit/test_agents.py` : client Mistral mocké (fixtures SDK
   `ToolExecutionEntry`/`FunctionCallEntry` comme T2.4) — boucle tool-calls, extraction
   JSON, rejets C1–C6, plafond anti-boucle ; `executer_outil` sur faux service Gmail
   (dry-run = aucune écriture).
4. **Vérifications** : `ruff`, `mypy src` (strict, `py-modules += agents`), `pytest` ;
   kanban → En revue ; commit/push sur demande (règle C).
