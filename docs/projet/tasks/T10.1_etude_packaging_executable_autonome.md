## Périmètre de l'étude (volet exécutable)

- Outils de packaging évalués (ex. PyInstaller) : dépendance de build ajoutée au groupe `dev`
  de `pyproject.toml`, script de build, taille et portabilité du binaire (cible Windows).
- **Point dur connu** : `RACINE_PROJET = Path(__file__).resolve().parents[2]` dans
  `src/gmailagent/core_config.py` résout `config/`, `data/` et `logs/` relativement à
  l'emplacement du fichier source — structure absente d'un binaire figé. Recodage de la
  résolution des chemins à prévoir (ex. répertoire de l'exécutable ou répertoire courant),
  avec tests associés.
- Invariants à préserver dans toute matérialisation : secrets via `os.environ` uniquement
  (règle D — jamais de secret embarqué dans le binaire), jeton OAuth Gmail dans `data/` hors
  binaire (permissions 600), dry-run par défaut (règle E), idempotence par libellés Gmail,
  corbeille uniquement pour la suppression.
- Alternative légère de distribution à un non-développeur (documentée en séance du
  11/11/2026, SESSIONS.md suite 13) : transfert de l'arborescence (sans `.venv/`, `data/`,
  `logs/`) + venv + `pip install -e .` (installation **éditable obligatoire** pour la
  résolution des chemins) + lanceur `.bat` appelant `.venv\Scripts\gmailagent.exe`.
